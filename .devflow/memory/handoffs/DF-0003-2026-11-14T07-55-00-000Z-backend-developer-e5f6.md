## Outcome

No backend change was required, and that is itself a finding worth recording.

The 502 was produced by the host-side proxy because the upstream TCP connect was
refused. It is not an application error, so no route handler, API, data model,
game rule or `GameEngine` code was touched. The application answered 200 on
every route before, during and after the fix; only the reachability of the
listener changed.

Verified that the running server serves the prefix build consistently with the
mount the proxy exposes, so the asset contract holds end to end:

- `/game` and `/game-center` → 200 on the prefixed server.
- The rendered HTML carries `/darthub/_next/...` for both stylesheets and
  scripts, and those exact URLs answer 200 on the container address.
- `/darthub/game` → 404 on the server itself. This is **correct**: Tailscale
  Serve strips the mount prefix before forwarding, so the backend must see
  `/game`. A 404 for `/darthub/game` at the backend is the healthy state; a 200
  there would mean the prefix was not stripped.

## Outcome

Implemented the game-engine throw ledger, replay-based recalculation and the undo/correct operations. RecordedThrow {playerId, points, segment?, bust} is carried in MatchState alongside a corrections audit list; visit grouping is DERIVED (MatchVisit + getVisits()), never stored, so it cannot go stale. GameEngine extracts recordThrow's body into a private applyToDraft(draft, record) that owns the dart counters, the turn advance and the completion check, and replay calls applyToDraft - not the mode directly - because turn order, counters and status are engine-owned (review finding C1). startMatch now retains playerIds, a copy of the MatchConfig and the matchId, and replay re-seeds from those via createSeedDraft, never via startMatch, so the checkout rule and leg structure survive (C2). GameEngineBustError extends GameEngineStateError and is thrown only for the bust case, so replay can distinguish a bust from a real failure while every existing error assertion still passes (C3). A correction is refused - changing neither state nor ledger - when the index is missing, the match is completed, the replacement would bust the corrected dart, or it would make a later recorded dart bust that previously did not (C4). undoLastThrow works on a completed match, so the match-winning dart can be undone (C5). A correction that changes the match result is audited via an optional mode-owned resultSignature hook, keeping the mechanism mode-agnostic (C6). The ledger is cloned in both directions between state and draft so a mode cannot mutate it by reference, and the payload bound is documented (I4). StandardMode was changed - outside the stated file list - because C3 and C6 require it.

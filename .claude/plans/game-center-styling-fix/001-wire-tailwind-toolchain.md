# Task 001: Wire up the Tailwind v4 toolchain and global stylesheet

**Status**: completed
**Depends on**: none
**Retry count**: 0

## Description
Install Tailwind CSS v4 and its PostCSS plugin, register the plugin with Next.js, create the global stylesheet that carries the Tailwind import and the base design tokens, and load that stylesheet from the root layout. Today the repo has no CSS pipeline at all, so every utility class in `app/` and `src/components/game/` is inert and the pages render with browser defaults.

## Context
- Related files:
  - `package.json` — add `tailwindcss` and `@tailwindcss/postcss` to `devDependencies` (both are free, open-source packages).
  - `package-lock.json` — **must be updated in the same change** (see "Lock file" below).
  - `postcss.config.mjs` — **new**; `export default { plugins: { "@tailwindcss/postcss": {} } };`
  - `app/globals.css` — **new**; the global stylesheet.

- Target version: Tailwind v4. Install it **unpinned** and let npm resolve the latest v4 of both packages:
  `npm install -D tailwindcss @tailwindcss/postcss`
  - Do **not** hard-code a version string in the plan or in the install command — the exact latest release must be resolved from the registry at install time, and `tailwindcss` and `@tailwindcss/postcss` must stay on the same major version.
  - Record the resolved versions (from `package.json`) in the task 004 report.
- v4 is CSS-first and needs **no** `tailwind.config.*` file — do not create one.

### Lock file (critical)
`Dockerfile` (deps stage) and `.github/workflows/ci.yml` both run `npm ci`, which fails hard when `package.json` and `package-lock.json` are out of sync (`EUSAGE: npm ci can only install packages when your package.json and package-lock.json are in sync`). Therefore:
- Install with `npm install -D …` — **never** hand-edit `package.json` to add the dependencies.
- After the install, confirm the lock file changed (`git status package-lock.json`) and that `npm ci` succeeds.

### Base design tokens for `app/globals.css`
Keep this file small and CSS-first. It should contain:
- `@import "tailwindcss";` — required first line.
- A `@layer base` block that sets the dark colour scheme on `html` and the page background / foreground colour on `body`, so every page inherits the theme instead of the browser default white background and black serif text.
  - The dark palette is already established by the pages: `bg-slate-900` / `text-slate-100` (see `app/game-center/page.tsx:45`).
  - Use `@apply` with the palette utilities so the base layer stays in the Tailwind theme system.
- **The body must also get the font stack applied** (`@apply font-sans` on `body`). The `h1` in `app/game-center/page.tsx:47` has no `font-*` utility, so it inherits the font-family from `body`; without this the page keeps the browser's serif default and task 003's font assertion fails.
  - Tailwind v4 already ships the `--font-sans` and `--font-mono` tokens, so `font-sans` / `font-mono` work out of the box. A custom `@theme` block is **optional** — add one only if a project-specific font stack is wanted. Do not add one "just in case": a hand-written font stack that omits a generic fallback (e.g. `sans-serif`) would break the page on machines without the named fonts.
- Where the compiled CSS lands: the production build emits it to `.next/static/css/*.css`. It is **not** copied into `.next/standalone` by Next.js — the `Dockerfile` copies `.next/static` separately (line 34). Inspect `.next/static/css/` when verifying, not `.next/standalone`.

**Deviation from the plan text — CSS output directory:** the plan states the compiled stylesheet lands in `.next/static/css/*.css`. That is only true for a **webpack** build. The plan explicitly forbids modifying `next.config.ts` and does not ask to change the `build` script, so the default Turbopack build was kept. The test therefore accepts **either** directory (`.next/static/css` or `.next/static/chunks`) and additionally asserts the built page (`game-center.html`) actually links the emitted stylesheet, so the assertion stays meaningful under either bundler.

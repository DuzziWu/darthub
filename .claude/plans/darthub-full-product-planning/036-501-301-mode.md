# Task 036: Implement 501 and 301 game modes in the engine

**Status**: completed
**Depends on**: 035
**Retry count**: 0

## Description
Add support for the classic "501" and "301" darts variants in the core game engine. Implement the start score, subtraction logic, and win condition when a player exactly reaches zero.

## Context
- File: `src/game-engine/modes/StandardMode.ts`.
- Uses the `GameEngine` API from Task 035.

## Requirements (Test Descriptions)
- [x] `it starts a match at 501 and allows scoring down to zero`
- [x] `it starts a match at 301 and behaves identically with a lower start score`
- [x] `it rejects throws that would reduce the score below zero (bust)`

## Acceptance Criteria
- Mode can be selected via a configuration object when creating a `GameEngine` instance.
- Unit tests cover normal play, bust, and win scenarios for both start scores.

## Implementation Notes

- Files: `src/game-engine/modes/StandardMode.ts` (mode), `src/game-engine/modes/index.ts` (mode barrel), `tests/unit/game-engine/modes/StandardMode.test.ts` (tests). Minimal core seam changes: `initializeMatch?(draft)` optional hook added to `DartGameMode` (`src/game-engine/types.ts`) and invoked in `GameEngine.startMatch` (`src/game-engine/GameEngine.ts`).
- Genuine seam gap fixed: `GameEngine.startMatch` initializes `totalPoints: 0` and the `DartGameMode` seam had no way to seed starting scores. Added the optional `initializeMatch?(draft: MutableMatchState): void` hook; it is a no-op for modes that omit it (NeutralScoreMode and CricketMode untouched, all pre-existing engine tests stay green).
- API: `new StandardMode({ startScore })` (config object per acceptance criteria), plus preconfigured `Standard501Mode` and `Standard301Mode` wrappers, exported from `src/game-engine/modes/index.ts`.
- Win condition: first player to land on exactly zero wins (`isMatchComplete` = some player at 0); mode id is `x01-<startScore>`.
- Bust semantics (as scoped by the orchestrator): plain subtraction only — a throw that would take the score below zero is a bust and is REJECTED via `GameEngineStateError` from `recordThrow`; state is left completely untouched (score, throwCount, throwsInCurrentTurn, turn order). "Lands on exactly 1" is currently NOT a bust (no double-out yet; from 1 a player can still finish with a single 1) — that rule, plus double-out/checkout variants, belongs to task 038.
- Extension seam for task 038: `protected resolveRemaining(remaining, points): number | null` in `StandardMode` — returns the new remaining score, or null for a bust. 038 can override/extend this (and the rejection strategy) for double-out and bust variants (e.g. revisiting the "reject vs. revert-to-turn-start + forfeit turn" decision made here, which will need turn-forfeit support in the core).
- Export strategy: modes are exported from a new `src/game-engine/modes/index.ts` barrel (NOT the root `src/game-engine/index.ts` barrel) to avoid write conflicts with the concurrent Cricket worker; the root barrel was not modified and needed no modification (tests import `GameEngine` from the root barrel and modes from the modes barrel).
